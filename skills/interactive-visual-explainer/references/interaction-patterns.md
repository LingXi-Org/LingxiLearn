# 交互教学模式

交互的意义是**暴露因果**，不是让页面动起来。选模式之前先写一句话：「操作完之后，学习者应该明白 ___」。这句话决定哪个变量该做成控件。

## 一、九种模式

| # | 模式 | 适用 | 控件 | 首帧必须已经说明的事 |
|---|---|---|---|---|
| 1 | **参数—输出探索** | 公式、阈值、损失函数、性能权衡 | 1–3 个滑块 | 一个代表性取值下的完整关系 |
| 2 | **步进执行** | 算法、协议、状态机、编译流程 | 上一步 / 下一步 / 复位 | 第 0 步的初始状态与数据结构 |
| 3 | **前后对照** | 变换、映射、归一化、编解码 | 切换开关 | 左右两侧的对应关系（连线或同色高亮） |
| 4 | **执行轨迹** | 排序、栈队列、动态规划、图算法 | 步进 + 变更高亮 | 数据结构初态 + 本步改了哪一格 |
| 5 | **抽样实验台** | 概率、置信区间、偏差方差、自助法 | 样本量滑块 + 重采样按钮 | 固定随机种子下的一次典型结果 |
| 6 | **几何操纵** | 向量、投影、导数、线性变换 | 可拖动控制点 + 等效数值输入 | 坐标轴、单位、当前坐标读数 |
| 7 | **结构剖析** | 系统架构、数据流、模型管线 | 点击节点展开细节 | 完整拓扑（点击只补细节，不补主干） |
| 8 | **时间游标** | 有序事件、训练阶段、时序协议 | 拖动游标 | 全时段的整体轮廓 + 当前时刻 |
| 9 | **阈值/相变对比** | 收敛与发散、稳定与失稳、分类边界 | 跨越临界值的滑块 | 临界值本身要标出来（虚线 + 标注） |

**首帧原则**：不许「必须先操作才能看懂基本结论」。交互是用来看**变化**的，基本事实要在静止时就成立。

## 二、控件规格

- **控件放在它所控制的图形的下方**，紧贴着那张图（`.controls` 紧跟在对应的 `</figure>` 之后）。这条没有例外：滑块、步进按钮、切换开关、时间游标都一样。
  - 为什么：拖滑块时手指或光标停在控件上，如果控件在上方，手就压在图的正上方；更要紧的是视线——控件在下，眼睛的落点是「图 → 变化」，控件在上则变成「控件 → 往下找图 → 再回来看值」，多一次往返。
  - 一张图配一组控件。有两张图各自可控时，各自在自己下面配一组，**不要合并成顶部一个总控制条**——那样就分不清哪个滑块在改哪张图了。
  - 图注（`<figcaption>`）在图与控件之间，读起来是「图 → 这张图说明什么 → 你可以怎么动它」。
  - 结果数值（KPI 卡）排在控件下方：改的是控件，看的是图，读的是数——三者自上而下各占一段。
- 控件集中放在一行（`.controls`），不要散落在图周围。
- 每个滑块必须配：左侧标签、右侧当前值 `<output>`（等宽 + `tabular-nums`）。值不显示等于没有滑块。
- `step` 一定要设，让控件本身只吐整值；再配 `toFixed(n)`。**任何显示到屏幕上的数字都要过取整**——`0.1 + 0.2` 会给你 `0.30000000000000004`。
- 控件总数 ≤ 3。第 4 个控件出现时，先问它是不是该换成两张图。
- 复位按钮是必需的，回到那个「典型例子」的状态。
- 用原生 `<input type="range">` / `<button>` / `<select>`，自带键盘可达。不要自己用 div 造滑块。

## 三、状态同步

一次 `render()` 里必须把**所有**依赖状态的东西一起更新：图形、数值卡、图例、标注、以及文字替代。最常见的 bug 是滑块动了、图变了，但下面那句结论文字还停在旧值上——这比不写结论更糟。

写法：把所有绘制逻辑收进一个 `render()`，事件只负责调它。不要在事件回调里各改各的。

```js
function render() { /* 读控件 → 算 → 全量重绘 → 更新 KPI/标注/alt */ }
lr.addEventListener('input', render);
render();                                  // 首帧
```

## 四、可访问性（每一条都是硬要求）

- 一个 `aria-live="polite"` 的段落，用一句话说明当前状态与结论。它同时服务于读屏用户、不渲染 JS 的客户端、以及打印。
- 关键信息不许只在 hover 里。触屏没有 hover，键盘也没有。要么常显，要么 focus/点击也能触发。
- 每张 SVG 有 `<title>`（必要时加 `<desc>`）。
- 颜色不是唯一编码：≥2 个系列必须有图例，≤4 个系列同时做直接标注。
- 用了动画就要有 `prefers-reduced-motion` 兜底（`lingxi.css` 里已内置）。

## 五、反模式

不要做这些：

- 用仪表盘来讲一个单一概念——仪表盘是给监控用的，不是给教学用的。
- 没有深度含义的 3D、粒子背景、装饰性动画。
- 学习者还没看懂基础情形，就先给一堆控件。
- 只是把动画当装饰：动效必须对应真实的时间演化或因果传递。
- 巨大的图例——能直接标在图元旁边就别做图例。
- 悬停才出现的关键数值。
- 随机数没有固定种子：除非「随机性」本身就是要讲的概念，否则每次刷新结果都不同会毁掉可复现性。

## 六、数据诚信

- 不许编造实测数据。示意用的数据必须在图注里写明「示意数据」。
- 单位必须可见。
- 涉及现实世界的数字（价格、人口、基准测试成绩）要先核实再画；核实不了就改用纯示意的抽象例子，并说明。
- 该保留的不确定性（误差棒、置信区间、缺失值）不要为了图好看而抹掉。
