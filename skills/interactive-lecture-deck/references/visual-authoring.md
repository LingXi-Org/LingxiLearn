# 视觉化 PPT 生成规范

这份规范复刻 `interactive-visual-explainer` 的核心制作理念，但将其改写为**静态 PPT 单页**：
结论要长在图里，不要长在段落里。

## 一、先写学习目标，再画页面

每页 content 在动手前先写一句内部目标：

> 学生看完这页，应该能**看出 / 判断 / 解释** ______。

如果目标动词只能写“知道 / 了解”，说明页面还没找到视觉关系。

## 二、优先选择“可看见的关系”

根据知识点选择：

- **结构** → 分层图 / 系统图 / 组成关系
- **过程** → 流程图 / 时序 / 状态迁移
- **变化** → 折线 / 参数变化图 / 前后状态
- **比较** → 对齐的双栏、矩阵、条形图、小多图
- **因果** → 输入→机制→输出
- **空间** → 几何示意 / 坐标 / 区域高亮
- **公式** → 把公式拆成变量角色、方向、约束与几何含义，不只写一行公式
- **例题** → 题面最小化 + 关键变换可视化 + 错误路径对照

如果一页只有“标题 + 3 个卡片 + 一段解释”，默认判为没有完成视觉设计。

## 三、首帧就要教会一件事

overview 时不看 panel，学生也应该获得一个明确判断。
因此：

- 标题写结论，如“拥塞不是链路变慢，而是排队开始累积”；
- 主图把因果画出来；
- panel 只补“为什么、怎么想到、哪里容易误判”。

## 四、文字压缩规则

页面文字按四级优先级删：

1. 保留：结论句、变量名、关键条件、轴标签、视觉对象名称。
2. 压缩：解释句 → 2–8 字标签；段落 → 关键词 + 箭头/空间关系。
3. 移入 panel：原因、直觉、类比、误区、边界条件。
4. 删除：过渡话、套话、重复标题、屏幕上已画明白的描述。

禁止“长句缩成稍短长句”。应把句子改造成**图形关系**。

## 五、学术图表反模式

命中即修改：

1. 双纵轴。
2. 3D 数据图表。
3. 彩虹色表达量级。
4. 颜色跟排名走而不是跟实体走。
5. 饼图用来精确比较多类别。
6. 每个点都标数。
7. 网格线比数据线重。
8. 大图例替代就地标注。
9. 图形没有一句可读的结论型标题。
10. 示意数据没有标注“示意”。

## 六、视觉反模式

1. 渐变 / 阴影 / 发光 / 模糊 / 玻璃拟态。
2. 600/700 字重。
3. emoji。
4. 仪表盘化：一页塞很多 KPI 小卡。
5. 一行塞 5 个以上小框。
6. 为装饰而画图形；每个图形都必须编码信息。
7. 彩色文字直接承担类别身份；类别色应落在形状/线条/色块上，标签文字仍以墨色为主。
8. 纯文字正文页。

## 七、zoom 讲解页反模式

1. 放大一个只有单词的小标签。
2. panel 逐字复述幻灯片。
3. 每一步都从全景拉回再推近；相邻 zoom 应连续平移。
4. 小窗盖住正在讲的对象。
5. 小窗像生成式 AI：频繁“接下来我们来看 / 可以看到 / 显然 / 综上所述”。
6. 小窗像逐字稿：一句超过 35–40 个汉字、整段没有停顿、层层列点。

## 八、交付前视觉审查

至少自问：

- 去掉 panel，这页首帧仍能让人抓住一个判断吗？
- 把所有正文删掉一半，信息是否反而更清楚？
- 主视觉是不是比标题+卡片更强？
- 颜色是否在编码含义，而不是装饰？
- zoom 到任何锚点后，局部是否像一张完整的小图？
