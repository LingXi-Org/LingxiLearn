# SVG 手艺：坐标、排版、手写图表

零依赖意味着**坐标要自己算**。这份文件是算错时的对照表。

## 一、画布约定

```html
<svg viewBox="0 0 680 H" role="img" aria-labelledby="fig1-t fig1-d">
  <title id="fig1-t">一句话说明这张图画的是什么</title>
  <desc id="fig1-d">补充说明，读屏用户会听到这句</desc>
  …
</svg>
```

- **宽度固定 680**，高度 H 随内容变。CSS 里 `width: 100%; height: auto`，浏览器按比例缩放。680 是为了让坐标单位在常见栏宽下接近 1:1，字号校准表才有意义。内容天然窄的图，**保持 680 并把内容居中**，不要把 viewBox 缩到贴合内容——一缩，14px 的文字就被放大成 20px。
- 安全区 x ∈ [40, 640]，y ∈ [40, H−40]。**不许出现负坐标。**
- H 的定法：所有元素最低点（矩形 y+height、文字基线 +4px 降部）+ 20px。别拍脑袋给个 500。
- 一个 `<figure>` 一张 `<svg>`。图形失败就整个替换，绝不在下面追加一个「修正版」。

## 二、文字（最容易翻车的地方）

**每个 `<text>` 必须带类**：`t`（14px 正文）、`ts`（12px 次级）、`th`（14px 中等字重）、`tn`（12px 等宽数字）。漏了类，暗色模式下会渲染成纯黑——因为 SVG 文字默认 `fill: black`。体检器会把这一项判 FAIL。

**只用两个字号**：14px 给节点标签，12px 给副标题和刻度。没有第三档。

**SVG 文字不会自动换行**，每一行都要显式 `<tspan x="…" dy="1.2em">`。如果副标题长到需要换行，那它就是太长了——砍到 5 个字以内。

**中文字宽估算**：14px 下中文约 14px/字，英文约 7.5px/字，数字约 8px/字。放进框之前算一遍：`文字宽 + 2×padding ≤ 框宽`。例如 6 个中文字在 14px 下约 84px，加左右各 16px padding，框至少 116px。

**`text-anchor="end"` 在 x < 60 处很危险**——文字向左延伸会越过 x=0。要么改用 `start` 然后右对齐整列，要么先验算 `字数 × 字宽 < x`。

**不许旋转文字。** 纵轴标题横排放在轴顶端。

## 三、连线与箭头

每张有箭头的图都以这段 `<defs>` 开头，且只放这一个 marker：

```html
<defs>
  <marker id="arrow" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="6" markerHeight="6" orient="auto-start-reverse">
    <path d="M2 1L8 5L2 9" fill="none" stroke="context-stroke" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/>
  </marker>
</defs>
```

`context-stroke` 让箭头自动继承所在线条的颜色，永远不会出现「灰线配蓝头」。

- **所有当作连线用的 `<path>`/`<polyline>` 必须写 `fill="none"`**，否则 SVG 默认填黑，一条曲线会变成一大块黑影。
- 线在部件边界处停住，用坐标算出停点，**不要画穿过去再用一个填充色块盖住**——背景色不保证是那个色。
- 结构容器用**虚线矩形加标签**，不要画拟物的外形（服务器机箱、细胞膜轮廓）。这是示意图不是插画。

## 四、把数据映射到坐标

固定四个边距常量，所有图表复用：

```js
const L = 60, R = 640, T = 40, B = 300;              // 绘图区
const px = x => L + (x - x0) / (x1 - x0) * (R - L);  // 数据 x → 屏幕 x
const py = y => B - (y - y0) / (y1 - y0) * (B - T);  // 数据 y → 屏幕 y（注意 y 轴翻转）
```

**刻度取整**：不要把 `[0, 4.37]` 直接映射。先把上界抬到「好数字」——`Math.pow(10, Math.floor(Math.log10(r)))` 求量级，再按 1 / 2 / 2.5 / 5 / 10 倍取整。刻度数控制在 4–6 个。

**折线**：拼 `d` 字符串时坐标保留 1 位小数（`.toFixed(1)`），能显著缩小文件体积且肉眼无差别。

**柱状**：柱宽 = 可用宽 / 根数 × 0.7，相邻柱之间留 2px 纸面色缝隙——不是靠间距，是靠一条 `--paper` 色的描边，这样堆叠段之间也能分开。

**散点**：半径 ≥ 4px；点重叠时加 1.5px 的 `--paper` 色描边（`.traj-dot` 就是这么做的），让叠在一起的点仍分得出个数。靠近坐标轴的点要把值域两端各留 10% 余量，否则圆会被裁掉。

**每根数据线 ≥ 2px，网格线 0.5px。** 网格永远比数据弱。

## 五、图表形式怎么选

先问「这张图的职责是什么」，再选形式。**有时答案不是图表**——单一结论就用一个大数字（KPI 卡），别硬画成只有一根柱子的柱状图。

| 数据的职责 | 形式 |
|---|---|
| 比较大小、排名 | 直接标注的条形图或点图（不是饼图） |
| 随时间变化 | 折线 + 可拖动的时间游标 |
| 构成占比 | 堆叠条（段间 2px 缝）；只有 2–3 项时用并排条 |
| 相关性 | 散点 + 可选的拟合线 |
| 分布 | 直方图或带抖动的点带 |
| 流程、状态机 | 节点-连线图 + 步进控件 |
| 层级、依赖 | 分层结构图 |
| 单一结论 | KPI 数字，不画图 |

**绝对禁止双纵轴。** 两个量纲不同的指标要么画两张图，要么归一到同一基准。这是图表里最常见也最严重的错误——双轴的交叉点位置完全取决于两个轴怎么缩放，看图的人会读出一个根本不存在的因果关系。

## 六、复杂度预算（硬上限）

- 框内副标题 ≤ 5 个字，展开细节放到正文或点击交互里。
- 一张图 ≤ 3 种颜色；颜色一旦编码含义就必须配一行图例。
- 同一行 ≤ 4 个框（每个约 140px）。5 个以上就缩到 110px、折成两行、或者拆成「总览图 + 细节图」两张。
- 排完一行就验算：左框的 `x + width` 要比右框的 `x` 小至少 20px。四个 160px 的框加三个 20px 间距是 700px，超过 640 的安全区，放不下——缩框或者砍副标题，不要让它们叠在一起。
- 不要给框加图标或插画，纯文字。
- 悬空的独立标签是噪声：每个 `<text>` 要么在框里，要么在图例里，要么是坐标刻度。箭头标签通常可以删掉——如果箭头的含义从起点终点看不出来，那该改的是框里的文字。
