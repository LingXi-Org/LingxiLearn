## 3.1 连接建立（三次握手）

建立连接使用三次握手：主动打开的一方发送 SYN 并携带自己的初始序号 ISN；
被动打开的一方回以 SYN+ACK，其中 ACK 确认对方的 ISN 加一，同时带上自己的 ISN；
主动方再发出 ACK 完成建立。握手的时间代价约为一个往返时延（RTT），
与服务器随后处理应用层请求所花的时间无关——这是两件事。

## 3.4 序号与确认

TCP 把数据当作一条无结构的字节流，为每个字节分配序号。
确认号是**累计**的：ACK = N 表示"序号 N 之前的所有字节我都已经正确收到，
现在期待从 N 开始的数据"。因此一个确认可以一次性确认多段数据，
而收到 ACK = N 并不意味着接收方只收到了第 N 段。

## 3.8.1 重传超时

发送方为未确认的数据维护一个重传定时器。定时器针对的是**窗口中最老的未确认数据**，
而不是每个报文段各自一个。定时器超时后，发送方重传那一段并退避定时器。
超时重传是可靠性的兜底手段，代价是至少一个 RTO 的等待。

## 3.8.2 重复确认与快重传

当接收方收到失序的报文段时，它会立即重复发出当前的累计确认，
表达"我要的还是这一段"。发送方连续收到三个重复确认，可以合理推断
该段已经丢失，而不必等待重传定时器超时——这就是快重传。
快重传把恢复时机从"等待一个 RTO"提前到"收到第三个重复确认"，
在丢包率不高的链路上能显著降低停顿。

## 3.8.6 发送窗口

发送窗口限制了"已发送但尚未被确认"的数据量。窗口有三个边界：
最老的未确认序号（base）、下一个待发序号（next）、以及窗口上界 base + window。
未确认量等于 next − base。窗口的推进由**收到的累计确认**驱动，
发送方不能自行前移窗口。窗口内仍有空位而发送方空等，是纯粹的吞吐浪费。

## 选择性重传与回退 N 步

当窗口中只有一段丢失时，把整个窗口全部重发（回退 N 步式的做法）不会破坏正确性——
接收方会识别并丢弃重复的数据——但会把接收方已经缓存好的失序段再传一遍，
白白消耗往返与带宽。只重传真正缺失的那一段，是更经济的选择。
