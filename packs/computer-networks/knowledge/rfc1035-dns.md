# RFC 1035 — Domain Names: Implementation and Specification

> source: https://www.rfc-editor.org/rfc/rfc1035.html

摘录用于教学引用。版权归 IETF Trust 所有，按 RFC 文档的通行条款用于教学引用。

## 4.1 报文格式

DNS 报文由首部和若干区段组成。首部包含 16 位事务 ID（ID）、标志位（QR 区分查询与响应、
RCODE 表示返回码），以及问题数、回答数等计数字段。**查询与响应通过事务 ID 配对**——
在抓包里把一次解析的起点和终点对应起来，靠的就是这个字段。

## 4.1.1 首部标志与返回码

QR 位为 0 表示查询，为 1 表示响应。RCODE 为 0 表示成功；
RCODE 为 3（NXDOMAIN）表示被查询的域名不存在。
NXDOMAIN 是一个**明确且快速**的失败，与"解析很慢"是完全不同的故障形态：
前者拿不到地址，后者只是拿得晚。

## 4.1.3 资源记录

响应中的每条资源记录包含名称、类型、类、TTL 和数据。
A 记录（类型 1）的数据部分是 4 字节的 IPv4 地址。
浏览器必须先从 A 记录拿到地址，才可能向它发出 TCP SYN。

## 5 传输与时延

DNS 查询通常承载在 UDP 53 端口上。一次解析的耗时是查询发出到响应到达之间的间隔；
如果本地缓存未命中且需要递归查询，这段时间可以达到上百毫秒。
**这段时间完整地发生在任何 TCP 连接建立之前**，因此在做页面加载时延归因时，
它是一个独立的、可以用两帧界定的环节。
